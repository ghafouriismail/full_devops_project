# DevOps Project

A 3-tier task manager application used as the workload for this DevOps pipeline.

---

## Architecture

```
┌─────────────────────────────────────────────────────┐
│                    Tier 1 — Frontend                │
│  src/frontend/                                      │
│  Vanilla HTML / CSS / JavaScript                    │
│  Served statically (any HTTP server / Nginx)        │
│  Communicates with the backend via REST (fetch API) │
└───────────────────────┬─────────────────────────────┘
                        │ HTTP  (JSON over REST)
                        ▼
┌─────────────────────────────────────────────────────┐
│                    Tier 2 — Backend                 │
│  src/backend/app.py                                 │
│  Python · Flask · Flask-SQLAlchemy                  │
│  REST API:  GET / POST / PUT / DELETE  /api/tasks   │
│  Runs on port 5000                                  │
└───────────────────────┬─────────────────────────────┘
                        │ SQLAlchemy ORM (DATABASE_URL)
                        ▼
┌─────────────────────────────────────────────────────┐
│                   Tier 3 — Database                 │
│  Dev:  SQLite  — src/backend/instance/tasks.db      │
│  Prod: PostgreSQL — configured via DATABASE_URL     │
│  Single table: tasks (id, title, done)              │
└─────────────────────────────────────────────────────┘
```

### Data flow

1. The browser loads `index.html` and `app.js` from the frontend tier.
2. On load (and after every mutation), `app.js` calls `GET /api/tasks` to fetch the task list.
3. User actions (add / toggle / delete) trigger `POST`, `PUT`, or `DELETE` requests to the Flask backend.
4. Flask validates the request, updates the database via SQLAlchemy, and returns JSON.
5. The frontend re-renders the list from the fresh response.

## Running locally (SQLite)

SQLite requires no setup — Flask creates the database file automatically on first run.

```bash
make run        # creates .venv, installs deps, starts http://localhost:5000
```

The database file is created at `src/backend/instance/tasks.db` on first request.
This path is git-ignored; you do not need to create it manually.

## Running with PostgreSQL (test / production)

### 1. Provision the database

Create a database and a dedicated user:

```sql
CREATE DATABASE tasks;
CREATE USER tasks_user WITH PASSWORD 'changeme';
GRANT ALL PRIVILEGES ON DATABASE tasks TO tasks_user;
```

### 2. Set the connection string

Copy the example env file and fill in your credentials:

```bash
cp src/backend/.env.example src/backend/.env
```

Edit `.env`:

```
DATABASE_URL=postgresql://tasks_user:changeme@localhost:5432/tasks
FLASK_DEBUG=0
FLASK_HOST=127.0.0.1
FLASK_PORT=5000
```

### 3. Start the backend

Load the env file and start the app:

```bash
export $(grep -v '^#' src/backend/.env | xargs)
make run
```

SQLAlchemy reads `DATABASE_URL` and connects to PostgreSQL instead of SQLite.
The `tasks` table is created automatically by `db.create_all()` on startup.

### Environment variable reference

| Variable | Default | Description |
|----------|---------|-------------|
| `DATABASE_URL` | *(unset → SQLite)* | Full SQLAlchemy connection string |
| `FLASK_DEBUG` | `0` | Set to `1` for auto-reload in local dev only |
| `FLASK_HOST` | `127.0.0.1` | Bind address (`0.0.0.0` to expose on all interfaces) |
| `FLASK_PORT` | `5000` | Port the backend listens on |

## Makefile targets

```
make install    Create .venv and install dependencies
make run        Start the Flask backend (http://localhost:5000)
make frontend   Serve the frontend separately (http://localhost:8080)
make compile    Regenerate requirements.txt from requirements.in
make lint       Black check + yamllint + Bandit
make format     Auto-fix Python formatting with Black
make clean      Remove the virtual environment
```
